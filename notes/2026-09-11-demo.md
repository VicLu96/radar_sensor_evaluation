# DEMO MILESTONE — BLE + web interface, 2026-09-11

Tag **`demo-2026-09-11`**. The node advertises, a browser connects, the sensor
boots on connection and streams frames to a live heatmap.

## Running it

```bash
# firmware
cd radar_sensor_evaluation/firmware_test
west build -b water_sense_board/nrf54l15/cpuapp . --pristine
west flash

# web interface
cd ../webinterface && npm install && npm run dev
```

Then **http://localhost:3000 in Chrome** → **Connect** → `water-sense-tof`.

The sensor is powered down until a client connects. The page subscribes on
connect, so the heatmap starts filling on its own.

## The configuration that works

| | | where |
|---|---|---|
| **Crystal load capacitance** | `internal`, 15000 fF HFXO / 17000 fF LFXO | app overlay — **without these the radio receives but cannot be heard** |
| AP_CLK | 12 MHz **external crystal**; GRTC output and P0.00 routing deleted | app overlay |
| Resolution | 54×42, 2268 zones | `prj.conf` |
| Exposure | 4 ms | `prj.conf` |
| I²C | **400 kHz**, 1040-byte concat buffers | app overlay |
| BLE | +8 dBm, 2M PHY, MTU 247, DC/DC | `prj.conf` |
| Flow | advertise → wait for connection → boot sensor → stream | `APP_BLE_FIRST`, `VL53L9CX_DEFER_BOOT`, `APP_BLE_AUTOSTREAM` |
| Size | FLASH 191,040 B (13.1%), RAM 113,736 B (59.1%) | |

## Two things that are NOT in this tag, deliberately

**1 MHz I²C.** One edit away in the overlay, and left out because it has not
been run and because the 4.7 kΩ pull-ups give a ~398 ns rise time against
Fast-mode Plus's 120 ns limit. A demo should not rest on an untested bus three
times outside spec. Fit 1 kΩ first — see
[../docs/plan/i2c-fast-mode-plus.md](../docs/plan/i2c-fast-mode-plus.md).

**Anything from the bring-up scaffolding.** `APP_BLE_ADV_SWEEP`,
`APP_BLE_RX_SELFTEST` and `APP_BLE_CHECK_HFXO` are all off. The code is still
in the tree and each returns in one line.

## Before demoing, check these on the bench

The milestone is tagged on a configuration Victor confirmed advertises and
connects. **Frame streaming end to end was not re-confirmed at the moment of
tagging**, so run it once before it matters:

1. Banner reads `VERSION: demo-2026-09-11` (or the tag plus a commit count).
2. `BLE link after powering the sensor: STILL UP`.
3. Heatmap fills, and the stats bar shows a drop rate near zero.
4. `capture` ≈ 334 ms, frame rate ≈ 2.5 fps — the I²C read is the ceiling.

## Known-open, and none of it blocks a demo

- **The IMU at 0x6B has been silent since 2026-09-10.** Unexplained. It is an
  LSM6DSV16BX (confirmed 2026-09-11) and does not gate anything here.
- **Crystal load capacitance values are Nordic's DK figures**, unverified for the
  ISP2454-LX. They work, which is not the same as correct — worth an email to
  Insight SiP, because a load close enough to advertise can still be tens of ppm
  out and show up as reduced range.
- **Intermittent laser faults**; the exposure backoff walks down and finds a
  working point. `CONFIG_VL53L9CX_EXPOSURE_BACKOFF` is still on and must come off
  before any energy measurement.
- **Full-resolution SNR is still unmeasured.** Amplitude at binning 2 against the
  126 measured at 24×20 is the number that says whether the paper's resolution
  axis is real.
